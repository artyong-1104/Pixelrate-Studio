### 직접 확인한 내용

게시자는 정수 배율로 확대된 픽셀아트를 학습 자료로 쓰고, 확대 시 최근접 이웃을 사용하며, 스프라이트 시트 프레임을 일정한 간격으로 배치하라고 제안한다. 4배와 8배 확대를 구분하는 트리거, 시트의 행·열 및 동작을 캡션에 명시하는 방법, 첫 프레임에서 나머지 프레임을 만드는 편집 학습을 설명한다. 출력 격자는 학습만으로 보장되지 않으므로 Perturbed Attention Guidance가 도움이 됐다고 주장한다.

연결된 Hugging Face 모델 카드는 해당 모델을 rank 16, 소량 데이터, 부족한 정규화로 학습한 실험작이라고 명시하고 결과 불일치도 공개한다. 카드의 후처리 워크플로는 각 프레임에 Perfect Pixel을 적용하고, 4×2 프레임의 발 기준점을 맞추고, 방향 전체에 공유한 32색 팔레트를 디더링 없이 적용한다. 즉 생성 모델 자체보다 후처리의 격자·정렬·팔레트 고정이 결과 규격을 보장한다.

### Pixelate Studio 적용 판단

- **직접 적용 가치 높음:** `2×/3×/4×/8×`처럼 정확한 정수 배율로 줄여 논리 픽셀 해상도를 출력하는 모드. 현재 정사각 모드는 비정사각 입력을 강제로 정사각형으로 만들고, 원본 규격 유지 모드는 논리 픽셀을 다시 원본 크기로 확대하므로 이 작업을 직접 제공하지 못한다.
- **실험 가치 높음:** 프레임별 자동 격자 감지 후 한 시트로 재조립하는 “AI 픽셀 격자 복구” 모드. 애니메이션에서는 프레임마다 독립적인 격자나 팔레트를 만들지 말고 시트 또는 시퀀스 단위로 잠가야 한다.
- **조건부 적용:** 투명 스프라이트의 발 또는 바닥 접점 정렬 진단. 자동 이동까지 하면 원래 모션을 훼손할 수 있으므로 먼저 앵커 오차 시각화와 수동 보정으로 제한하는 편이 안전하다.
- **범위 밖:** LoRA 학습·추론을 브라우저 앱에 포함하는 것. 모델 크기, GPU 요구, 비결정성, 라이선스 때문에 현재의 로컬 결정론적 후처리 도구와 맞지 않는다.

### 한계와 검증 질문

게시자와 모델 카드 모두 모델의 데이터 부족과 불안정성을 인정한다. 4배/8배, rank, 학습 스텝, PAG 값은 이 특정 모델의 경험치이며 일반 규칙으로 채택할 근거가 부족하다. 우리 프로젝트가 가져올 것은 생성 설정이 아니라 정수 배율, 프레임 규격, 공유 팔레트, 후처리 결정성이다.

### 직접 확인한 내용

게시자는 고해상도에서 영상을 만든 뒤 배경 제거와 결정론적 픽셀화를 수행한다. 애니메이션에서 팔레트를 시퀀스 전체로 한 번만 만들고, 격자 원점을 고정하고, 디더링을 끄지 않으면 프레임 간 지글거림이 생긴다고 보고한다. 80px에서 8등신 캐릭터의 눈이 약 2px밖에 되지 않아 후처리만으로 표정을 복구할 수 없었고, 치비 비율이나 더 높은 출력 해상도가 픽셀 예산을 늘렸다고 설명한다. 확대 화면에서만 판단하지 말고 실제 사용 크기로 보라는 결론도 제시한다.

실패 기록도 구체적이다. 블록 최빈값 축소는 큰 경계를 단단하게 하지만 앞머리, 입, 눈동자 하이라이트 같은 작은 특징을 지웠다. 팔레트 양자화만 추가한 결과는 정지 화질을 개선하지 않았고 일부 계단 현상을 만들었다. 반면 고해상도 라인 검출 후 축소 결과에 합성하는 방법과 실루엣 최외곽을 어둡게 하는 `selout`은 자체 예시에서 효과가 컸다고 보고한다. 공개 코드에는 알파 가중 축소, 결정적 OKLab K-means, MedianCut, Weber 대비 기반 가중 축소, 라인 커버리지 합성, selout이 구현되어 있다.

배경 제거 부분에서는 soft alpha를 그대로 쓰면 밝은 불투명 의상이 반투명 얼룩이 되었고, 단순 이진화가 한 데이터에서는 개선됐다고 보고한다. 그러나 검은 외곽선과 크로마 배경이 섞인 경계는 RGB 거리 키로 제거하면 색이 남았고, 키 색상의 채널 관계를 이용한 색차 키와 언믹싱이 더 적합했다고 주장한다. 다른 캐릭터에서는 의상에 마젠타가 있어 마젠타 키가 실패했으며, 입력에서 덜 쓰이는 색상환 구간을 키 색으로 선택했다.

### Pixelate Studio 적용 판단

- **바로 반영할 UX 원칙:** 1× 실제 크기와 2× 게임 표시 크기를 원클릭으로 비교하고, 여러 프레임 또는 시트를 루프로 재생해 시간축 흔들림을 검사한다. 현재 모달은 1~24배 확대가 가능하지만 처음에는 화면 맞춤 배율로 열리고 원본/결과 비교나 애니메이션 재생이 없다.
- **기존 강점 유지:** 여러 입력의 공유 팔레트와 결정론적 처리. 시트 한 장은 이미 전체 시트에서 팔레트를 뽑는다. 이 동작을 “애니메이션 안전” 프리셋으로 명확히 묶고, 격자·팔레트·디더링 정책을 함께 잠그는 것이 좋다.
- **실험 후보:** 현재 sRGB 유클리드 K-means와 OKLab 매핑/MedianCut을 비교한다. OKLab은 지각적 색 차이를 다루는 후보지만, 면적이 큰 색이 팔레트를 독식하는 문제는 별도로 남는다.
- **실험 후보:** 기존 Box 축소와 Weber 가중 축소 + 라인 커버리지 합성 + 선택적 외곽선을 비교한다. 기존 외곽선 기능을 대체하지 말고 별도 “세부 보존” 후보로 시험해야 한다.
- **제품 후보:** 불투명 스프라이트용 알파 이진화와 반투명 보존을 명시적으로 분리한다. 현재 구현은 `alpha >= 10`만 남기고 최종 알파를 255로 만들어 사실상 항상 이진화한다.
- **보류:** 자동 배경 제거와 범용 크로마 키. 유용하지만 현재 입력 변환 도구의 범위를 크게 넓히며, 색 선택·언믹싱·경계 밴드·위상 보존까지 별도 검증이 필요하다.

### 한계와 검증 질문

수치와 우선순위는 한 제작자의 특정 캐릭터·모델·해상도에서 얻은 자체 결과다. 공개 코드는 실제 접근 가능했지만 저장소 루트에서 명시적 라이선스 파일을 찾지 못했으므로 코드를 복사하지 말고, 아이디어를 독립 구현하거나 라이선스를 먼저 확인해야 한다. Weber/라인/selout의 상대적 기여는 우리 고정 코퍼스에서 분리 실험해야 한다.

### 직접 확인한 내용

게시글 자체는 “90% 맞는 이미지를 100% 맞게 만든다”는 짧은 추천뿐이며 비교 조건이나 측정치는 없다. 따라서 “가장 성능이 높다”는 평가는 검증되지 않았다.

연결된 Perfect Pixel 코드는 더 유용한 근거를 제공한다. FFT magnitude에서 반복 격자의 초기 크기를 찾고, 실패 시 Sobel 경계 간격으로 대체하며, 예상 격자선 주변에서 강한 경계를 찾아 셀 경계를 조정한다. 각 셀의 대표색은 center, median, majority 중 선택한다. 수동 `grid_size`, 최소 셀 크기, peak 폭, refinement 강도도 제공한다. 패키지 메타데이터는 MIT를 선언하지만 조사 당시 루트 LICENSE 파일 URL은 404였다.

### Pixelate Studio 적용 판단

- **핵심 실험 후보:** “블록 크기를 사용자가 이미 안다”는 현 구조 옆에 자동 감지와 신뢰도 표시를 추가한다. 감지 실패 시 현재의 수동 프레임·블록 입력으로 돌아가야 한다.
- **구현 순서:** 브라우저에서 먼저 Sobel 투영 + 주기/오프셋 추정의 단순 버전을 시험한다. FFT는 장점이 입증될 때만 JS 또는 WASM으로 추가한다.
- **애니메이션 안전:** 프레임마다 제각각 감지하지 말고 현재의 수동 frame bounds 안에서 후보를 구한 뒤 공통 period/phase에 합의시켜 모든 프레임에 적용한다. 전체 시트를 그대로 FFT/Sobel 분석하면 논리 픽셀보다 프레임 간격이나 투명 여백 주기를 잡을 수 있다. Source 01의 연결 모델 카드는 프레임별 감지 후 작은 위치·배율 검색을 쓰지만, 우리 앱에서는 시간축 흔들림 방지가 우선이다.
- **대표색 옵션:** center/median/average/majority를 A/B 비교한다. Source 02의 결과처럼 majority는 작은 특징을 지울 수 있으므로 기본값으로 채택하면 안 된다.

### 한계와 검증 질문

공개 구현은 주기적인, 대체로 정사각형인 셀과 충분한 경계를 가정한다. 사진처럼 암시적 격자가 없는 입력, 저대비 이미지, 큰 단색 영역, 투명 가장자리, 서로 다른 픽셀 크기가 섞인 시트에서 실패 가능성이 크다. 원 코드의 주요 경로는 RGB/BGR 중심이라 RGBA와 프레임 경계 처리를 별도로 설계해야 한다.

### 직접 확인한 내용

게시자는 LoRA가 만든 픽셀풍 이미지는 격자가 정확하지 않으므로 “의도했던 사이즈로 줄이고 색을 제한”한 뒤 수동 리터칭해야 한다고 설명한다. 학습 자료가 원본 픽셀아트의 정확한 8배였다면 결과를 8배 줄이고, 배경 확장 결과가 약 3배 커졌다면 3배 줄이는 식으로 생성 파이프라인의 알려진 배율을 역으로 적용한다. 캐릭터와 배경의 픽셀 크기·색온도·색조가 달라 따로 노는 문제도 지적한다.

첨부 화면에서 768×1344 생성물이 멀리서는 픽셀아트처럼 보이지만 확대하면 고정 8×8 셀 안에 여러 색과 엇갈린 경계가 있다. ComfyUI Pixelate 노드는 `rescale_to_original=false`, `colors=256`, `dithering=none`으로 설정되어 있고, 96×168 native 결과와 nearest-exact로 다시 키운 768×1344 결과를 분리해 저장한다. 배경 사례는 Sprite Size 33.32%·Nearest-Neighbor로 약 3배 축소하며, 축소 뒤 의자·가구의 얇은 경계가 일부 끊긴 모습을 작성자도 지적한다. 밝은 초록 배경에서 누끼 가장자리와 잔여 픽셀을 수동 검사하는 장면도 확인했다.

### Pixelate Studio 적용 판단

- **우선 적용:** 정사각 목표 크기뿐 아니라 `1/n` 배율 또는 계산된 너비×높이로 종횡비를 보존하는 출력. Source 01·02·07과 반복해서 일치한다.
- **우선 적용:** native 저해상도 PNG와 선택적 2×/4×/8× nearest 확대 PNG를 한 번에 내보내는 옵션. 논리 픽셀 편집용과 게임 표시용 산출물을 분리한다.
- **제품 안내:** “AI 픽셀풍 정리” 프리셋은 정수 배율 축소, 팔레트 제한, 고립 픽셀 정리를 묶되 결과가 자동 완성품이라고 표현하지 않는다.
- **진단 후보:** 여러 에셋의 논리 픽셀 크기와 팔레트 차이를 나란히 보여 주어 캐릭터/배경의 스케일 및 색조 불일치를 발견하게 한다.
